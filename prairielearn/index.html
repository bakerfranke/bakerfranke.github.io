01 What PrairieLearn is

PrairieLearn is an open-source, auto-gradable homework and exam platform — students answer coding, math, and interactive questions and get scored automatically wherever possible. UIC runs a hosted instance of it; CS 111 lives there as one course among many.

There are two separate repositories in play, and it matters which one you're in:

PrairieLearn/PrairieLearnplatform

The engine itself — the app that renders questions, runs the grader, serves the site. You will basically never need this repo.

PrairieLearn/pl-uic-cs111content

Our course's actual questions and assessments — plain files in a git repo. This is the one you'll clone and live in.

02 Get it running

Goal: clone the content repo, run a local copy of PrairieLearn against it in Docker, and confirm you can browse CS 111's questions. Fifteen minutes, no one else's help required.

  1. Clone the course repo

    Ask Baker for repo access first if you don't have it yet.

    git clone https://github.com/PrairieLearn/pl-uic-cs111.git

  2. Install Docker Desktop

    PrairieLearn ships as one Docker image — you don't build the platform from source. Grab it from docker.com/products/docker-desktop, install it, open it once, and wait for the whale icon to say it's running.

  3. Run PrairieLearn, pointed at the repo

    This mounts your local checkout into the container at /course. Swap in your actual path.

    docker run -it --rm -p 3000:3000 \
  -v ~/path/to/pl-uic-cs111:/course \
  prairielearn/prairielearn:us-prod-live

    The us-prod-live tag matches what's actually running our live course — closer to reality than the bleeding-edge default image.

  4. Load the course and look around

    Open localhost:3000/pl, click Load from disk in the top bar, and confirm CS 111: Program Design I shows up. Click into a question and hit Preview — you're now looking at a fully local, editable copy of the course.

Editing loop, once it's running

HTML / Python changes (question.html, server.py) — just reload the page in the browser.

JSON changes (info.json, infoAssessment.json) — click Load from disk first, then reload.

⚠ One thing this simple command can't do

Questions that auto-grade actual student-submitted code (not just a number or click) need "external grading" — PrairieLearn spins up a second, disposable Docker container per submission to run the code safely. The command above doesn't enable that. See §04 for what that means and which flags fix it — ask Baker if you hit a submission that just hangs.

04 Anatomy of a question

Every question folder has the same three core files. server.py always runs, but what it's responsible for depends on the grading method.

FileRole
info.jsonTitle, topic, UUID, and — critically — gradingMethod.
question.htmlMustache template. {{params.x}} is escaped, {{{params.x}}} drops in raw HTML built by server.py.
server.pygenerate() builds random params + the correct answer. grade() is optional, in-process scoring for value-type answers.

The three grading methods

MethodWhere code runsUse for
Internal Inside PrairieLearn's own server process — safe because the student only submits a value (a number, a click, a multiple-choice pick). Numeric answers, multiple choice, pl-drawing click-to-place questions.
External A second, disposable Docker container spun up per submission — the student's actual code gets executed there, isolated from the real server. "Write a function that…" coding questions. Needs an image, an entrypoint, and usually a tests/ folder in info.json.
Manual Nowhere — code is just saved. A human opens PrairieLearn's grading UI later and scores it by hand. Open-ended or design-y responses that can't be mechanically checked.

05 Getting a change live

The live site at us.prairielearn.com only ever reflects whatever is on this repo's master branch — and only after someone pulls it in. There's no way to preview a feature branch on the hosted site; that's what your local Docker copy is for.

  1. Branch, edit, push

    Work locally against Docker, same as §02, until it looks right.

  2. Open a PR, get it reviewed and merged to master

  3. Sync it on the live site

    An Editor/Owner goes to the course's Sync page and clicks Pull from remote git repository. Merging alone does not update the live course — this step is easy to forget.

There's also an in-browser file editor on the live site for quick one-off edits — it commits straight to master, bypassing review. Fine for typo fixes; use the git flow for anything that touches grading logic.

07 Open problem: Karel-style questions

⚠ Unsolved — good use of your background here

We don't have a settled pattern for Karel-the-Robot questions yet. Two incompatible approaches exist in the repo right now: my own karel-world-drawing-test (hand-rolled canvas + JS, fragile grading) and the colleague's pl-drawing-based graph-start-end (native tolerance-based grading, but wasn't built with Karel's fixed four-direction facing in mind).

Given you've managed engineering teams before, this is less "figure out PrairieLearn syntax" and more an actual design decision: pick one direction, or a hybrid, and prototype it. I have some half-formed ideas (representing Karel's facing as one of four preset pl-vector angles rather than a freehand point) — worth a real conversation before you sink time into it.
